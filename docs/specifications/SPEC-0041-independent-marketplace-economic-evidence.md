# SPEC-0041: Independent Marketplace Economic Evidence

Status: Proposed

Date: 2026-08-27

Source decision: ADR-0042

## Objective

Accept independently arriving marketplace economic and identity evidence for
one organization-scoped order without requiring ERP sales-order identity,
inventing missing values, silently replacing facts, allocating Ads spend, or
activating infrastructure.

## Authorized next implementation

Acceptance authorizes TASK-0140 only:

1. add one pure production file under the existing
   `io.flooow.marketplace.operations.economics.evidence` package;
2. reuse all existing organization, order, marketplace, currency, component,
   money, source, quality, and coverage types;
3. add the exact subject, identifier, family, financial observation, external
   identity observation, collection attempt, correction, immutable evidence
   set, controlled merge result, and merger specified here;
4. enforce subject isolation, family/payload compatibility, authoritative zero,
   duplicate, conflict, append-only attempt, and explicit supersession rules;
5. prove the accepted MGI v0.7.6 parallel evidence scenarios and no-regression
   behavior with focused provider-free tests;
6. change no existing production type, calculation, ledger, reconciliation,
   pricing, API, persistence, runtime, connector, inventory, or Kernel behavior;
7. add TASK-0140 evidence and update the executive journal.

No live Mercado Livre or Omie call, persistence, migration, API, event,
projection, UI, automatic action, or AI is authorized.

## Subject

```text
MarketplaceEconomicEvidenceSubject(
  organizationId,
  orderId,
  marketplace,
  externalOrderId,
  currency
)
```

The subject reuses existing value types. It is immutable, value-equal, and
renders `[REDACTED]`.

Every retained observation, attempt, and correction must belong to exactly the
same subject instance by value. No cross-organization, cross-order,
cross-marketplace, cross-external-order, or cross-currency merge is permitted.

## Observation identifier

```text
MarketplaceEconomicEvidenceObservationId
```

The identifier wraps a canonical lowercase UUID. Parsing rejects noncanonical,
uppercase, malformed, or whitespace-bearing values. It provides value
equality, an internal UUID accessor only where required by canonical sorting,
and `[INTERNAL]` rendering.

No random identifier is generated by the domain.

## Financial observation

```text
MarketplaceEconomicComponentObservation(
  id,
  subject,
  family,
  component,
  coverageClaim,
  observedAt
)
```

Invariants:

1. component organization equals subject organization;
2. component order equals subject order;
3. component currency equals subject currency;
4. coverage claim is `COMPLETE` or `PARTIAL` only;
5. `observedAt` is whole-microsecond aligned;
6. `observedAt >= component.occurredAt` only for `MANUAL` and `CALCULATED`
   sources; provider clocks are retained without an ordering claim;
7. family and component type follow this exact table:

```text
MARKETPLACE_ORDER
  REVENUE | MARKETPLACE_COMMISSION | MARKETPLACE_FEE

MARKETPLACE_SHIPPING
  SHIPPING

PRODUCT_COST
  PRODUCT_COST

FISCAL_TAX
  TAX

ADS_ALLOCATION
  ADVERTISING
```

All other combinations are invalid. `MARKETPLACE_PAYMENT`, `FISCAL_INVOICE`,
and `ADS_IDENTITY` never carry an `EconomicComponent` in this contract.

A zero component magnitude is valid and known. No constructor treats zero as
missing. Negative magnitudes remain rejected by `EconomicComponent`.

The observation renders `[REDACTED]`.

## External identity kind and observation

```text
MarketplaceEconomicExternalIdentityKind
  MARKETPLACE_PAYMENT
  ERP_ORDER
  FISCAL_INVOICE
  MARKETPLACE_ITEM_TO_AD_GROUP
```

```text
MarketplaceEconomicExternalIdentityObservation(
  id,
  subject,
  family,
  kind,
  anchorReference,
  linkedSystemKey,
  linkedReference,
  source,
  occurredAt,
  observedAt
)
```

Family and kind must match:

```text
MARKETPLACE_PAYMENT -> MARKETPLACE_PAYMENT
FISCAL_INVOICE      -> FISCAL_INVOICE
ADS_IDENTITY        -> MARKETPLACE_ITEM_TO_AD_GROUP
MARKETPLACE_ORDER   -> ERP_ORDER
```

`anchorReference` and `linkedReference` reuse
`EconomicExternalReference`; `linkedSystemKey` reuses
`EconomicSourceSystemKey`; source reuses `EconomicSource`.

Both times must be whole-microsecond aligned. For `MANUAL` and `CALCULATED`
sources, observation time must not precede occurrence time. Provider clocks
receive no ordering inference in this contract.

The observation contains no amount, currency conversion, coverage claim,
confidence score, matching score, or allocation policy. It renders
`[REDACTED]`.

An Ads identity observation cannot be converted to an `ADVERTISING` component
by any API in this file.

## Correction

```text
MarketplaceEconomicEvidenceCorrectionReason
  SOURCE_CORRECTION
  MAPPING_CORRECTION
  VERIFIED_MANUAL_CORRECTION
```

```text
MarketplaceEconomicEvidenceCorrection(
  id,
  subject,
  replacement,
  supersedesObservationId,
  reason,
  observedAt
)
```

The correction identifier and replacement observation identifier must differ
from the superseded identifier and from each other. Correction time is
whole-microsecond aligned and must not precede the replacement observation
time. The replacement must belong to the same subject.

The merger additionally requires that the superseded identifier identifies an
active accepted fact, not an attempt or correction, and has not already been
superseded. Correction chains cannot cycle because a replacement identifier is
new and an active fact may be superseded once.

Corrections preserve the prior fact. They do not mutate it. The correction and
all its identifiers render `[REDACTED]` or `[INTERNAL]` as appropriate.

## Immutable evidence set

```text
MarketplaceIndependentEconomicEvidence(
  subject,
  facts,
  attempts,
  corrections
)
```

Construction is internal. The empty factory requires one subject. Collections
are immutable snapshots in canonical order:

1. observation/correction time ascending;
2. unsigned canonical UUID order as a total tie-breaker.

The aggregate validates:

- every retained item has the exact subject;
- all identifiers across facts, attempts, and corrections are globally unique;
- correction targets and replacements exist and are consistent;
- one accepted fact is superseded at most once;
- no correction cycle or dangling link exists;
- no duplicate financial source fact exists among active facts.

It exposes active and historical facts separately. Historical access never
removes superseded facts. It performs no Economic Truth calculation or
component-coverage aggregation.

The aggregate is value-equal, immutable, deterministic, and renders
`[REDACTED]`.

## Financial source-fact identity

For marketplace and ERP component sources, the active source-fact key is:

```text
source.kind
+ source.systemKey
+ source.externalReference
+ component.type
```

The external reference is already mandatory for those source kinds.

For manual and calculated sources with an absent external reference, no
provider identity is invented. Observation identifier is the uniqueness key.

Equal source-fact identity and equal economic meaning is a duplicate source
fact. Different magnitude, direction, occurrence time, quality, or coverage
claim is a conflict requiring explicit correction.

```text
MarketplaceIndependentEconomicEvidenceMerger.apply(

```

The merger reads no clock, repository, environment, or provider.

## Deterministic validation order

For every update:

1. update subject equals aggregate subject;
2. update shape and family compatibility are valid by construction;
3. update identifier is globally unused, or exact prior payload is classified
   duplicate;
4. a reused identifier with different payload is conflict;
5. for a new financial fact, active source-fact duplicate/conflict is checked;
6. for correction, superseded fact exists;
7. correction does not target an attempt or correction;
8. superseded fact is active and not already superseded;
9. replacement identifier is globally unused;
10. replacement does not create an active source-fact conflict with another
    fact;
11. append and return the canonical new aggregate.

The first disagreement returns its controlled result. No partial aggregate is
returned on failure.

## Controlled result

```text
sealed interface MarketplaceIndependentEconomicEvidenceResult {
  Applied(evidence)
  Duplicate(evidence)
  SubjectMismatch
  IdentifierConflict
  SourceFactConflict
  SupersededFactNotFound
  SupersededTargetNotFact
  FactAlreadySuperseded
  ReplacementIdentifierConflict
  ReplacementSourceFactConflict
}
```

`Applied` and `Duplicate` retain the exact current or new evidence aggregate as
specified. Failures retain no subject, fact, amount, source, reference,
timestamp, identifier, correction, or partial aggregate. Every result renders
`[REDACTED]`.

## Accepted MGI v0.7.6 scenarios

TASK-0140 must reproduce these provider-free states:

### Authoritative zero shipping

An exact `SHIPPING` deduction of `0 BRL`, sourced from a stable marketplace
shipment-cost reference with `COMPLETE` coverage, is accepted while ERP order
identity is absent.

### Missing shipping

A `NO_EVIDENCE` shipping attempt appends to attempts and leaves no shipping
component. Repeating a missing attempt never removes a previously accepted
shipping component.

### Product COGS without ERP order

One exact `PRODUCT_COST` component sourced from stable Omie product-cost
evidence is accepted independently of ERP order identity.

### Invoice and tax without ERP order

An exact invoice identity and a separate `TAX` component are accepted without
ERP order identity. The invoice identity alone creates no tax component.

### Ads identity without allocation

One or more item-to-Ad-Group identity facts are accepted. No advertising
component or Ads coverage claim appears until an explicit `ADS_ALLOCATION`
financial fact arrives.

### Provider failure after known fact

A later `TEMPORARY_FAILURE` or `NO_EVIDENCE` attempt appends without changing
the known fact or its provenance.

### Conflicting provider fact

The same financial source-fact key with a different amount returns
`SourceFactConflict`. An explicit valid correction preserves the old fact,
marks it superseded, and activates the replacement.

## Precision and privacy

- accepted new timestamps use whole-microsecond precision;
- no float, double, binary decimal conversion, rounding, or string arithmetic
  is introduced;
- all financial values remain `MarketplaceMoney`;
- exception messages are generic and contain no values;
- all aggregate, fact, observation, attempt, correction, merger, and result
  renderings are redacted;
- no organization, order, marketplace, external order, currency, source,
  external reference, amount, timestamp, coverage, family, kind, or reason is
  exposed through rendering.
