# SPEC-0021: Marketplace Financial Trace and Economic Ledger

Status: Proposed

Date: 2026-08-13

Source decision: ADR-0021

## Objective

Persist an immutable organization-owned financial trace from one normalized
marketplace order through settlement, payment account, and bank facts, while
preserving expected and actual evidence separately and performing no
reconciliation judgment.

## Trace command and record

```text
OpenFinancialTrace(
  organizationId,
  requestId,
  orderId,
  marketplace,
  externalOrderId,
  currency
)
```

```text
FinancialTrace(
  organizationId,
  id,
  orderId,
  marketplace,
  externalOrderId,
  currency,
  openedAt,
  entries
)
```

The command and record are immutable and redact aggregate rendering. The
repository receives the trace ID separately from the open command.

One organization may have at most one trace per `MarketplaceOrderId`. Opening
the same request with value-equal material returns the original trace ID.
Reusing the request with different material returns `Conflict`. A different
request for an already traced order returns `OrderAlreadyTraced` with the
existing trace ID only when the stored order root is value-equal; incompatible
stored root material is `IntegrityFailure`.

Opening requires an active organization at transaction time.

The repository receives the entry ID separately from the draft. All records

## Source facts

The draft reuses `EconomicSource` exactly. `MARKETPLACE` and `ERP` therefore
require `Present(EconomicExternalReference)`; `MANUAL` and `CALCULATED` may use
`Absent(INTERNAL_ORIGIN)`.

For a present reference, the organization-global source fact key is:

```text
(organization, source kind, source system key,
 external reference, stage, basis)
```

An exact repeated source fact returns `AlreadyAppended(existingEntryId)` even
when the append request ID differs. A repeated key with any different trace,
direction, magnitude, occurrence time, or correction target returns `Conflict`.

An absent internal reference has no source-fact key and relies on append request
replay.

## Append request replay

The append request key is `(organization, requestId)`.

An exact replay returns `AlreadyAppended(existingEntryId)`. Reusing it with a
different trace, stage, basis, direction, magnitude, source, occurrence time,
or correction target returns `Conflict`.

Entry IDs are unique within an organization. A colliding caller-supplied entry
ID with different material fails closed as `Conflict`.

## Correction chain

When `correctsEntryId` is present, append requires that the target:

1. exists in the same organization;
2. belongs to the same trace;
3. has the same stage and basis;
4. has no existing direct correction.

The replacement may change direction, magnitude, source, and occurrence time.
A correction may itself be corrected later, creating one linear chain.

Unknown, foreign, cross-trace, stage-mismatched, basis-mismatched, or already
corrected targets return `CorrectionTargetUnavailable` or `Conflict` without
inserting anything. The database mirrors these invariants with a deferred
constraint trigger and a unique partial index on correction target.

## PostgreSQL V014

### `marketplace_financial_trace`

```text
organization_id uuid
trace_id uuid
open_request_id uuid
order_id uuid
marketplace_key text
external_order_id text
currency char(3)
opened_at timestamptz
```

Constraints:

- primary key `(organization_id, trace_id)`;
- unique `(organization_id, open_request_id)`;
- unique `(organization_id, order_id)`;
- organization foreign key to `integration_organization`;
- marketplace key matches `[a-z0-9][a-z0-9.-]{0,99}`;
- external order UTF-8 byte length is 1..256, trimmed, and control-free;
- currency matches `[A-Z]{3}`.

### `marketplace_financial_ledger_entry`

```text
organization_id uuid
entry_id uuid
append_request_id uuid
trace_id uuid
stage text
basis text
direction text
magnitude numeric(24,6)
source_kind text
source_system_key text
external_reference text nullable
external_reference_absence_reason text nullable
occurred_at timestamptz
recorded_at timestamptz
corrects_entry_id uuid nullable
```

Constraints:

- primary key `(organization_id, entry_id)`;
- unique `(organization_id, append_request_id)`;
- composite trace foreign key;
- self foreign key `(organization_id, corrects_entry_id)`;
- unique partial index `(organization_id, corrects_entry_id)` when present;
- exact controlled stage, basis, direction, source-kind, and absence-reason
  checks;
- magnitude is non-negative and below `1000000000000000000`;
- source-system key matches `[a-z0-9][a-z0-9.-]{0,99}`;
- present external reference is 1..256 UTF-8 bytes, trimmed, and control-free;
- MARKETPLACE/ERP requires a present external reference;
- MANUAL/CALCULATED requires either present reference or `INTERNAL_ORIGIN`;
- external reference and absence reason are mutually exclusive;
- partial unique source-fact index over organization, source kind/system,
  external reference, stage, and basis when reference is present.

V014 adds immutable update/delete rejection triggers for both tables. A deferred
entry trigger validates active organization for insert, trace ownership, and
correction target trace/stage/basis. A trace insert trigger validates active
organization. No trigger calculates reconciliation.

## Transactional open

The PostgreSQL adapter:

1. starts a transaction;
2. checks exact request replay;
3. locks the active organization row;
4. checks whether the order already has a trace;
5. inserts the root with transaction time;
6. commits;
7. on a concurrent constraint failure, re-reads request/order state and returns
   the same controlled replay/conflict outcome.

No SQL/constraint/error detail escapes in a result or exception message.

## Transactional append

The PostgreSQL adapter:

1. validates pure draft shape;
2. starts a transaction;
3. checks exact request replay;
4. locks the active organization and trace roots;
5. checks exact present-source replay;
6. when correcting, locks and validates the target and absence of a successor;
7. validates trace currency;
8. inserts one entry using transaction time;
9. commits;
10. on a concurrent constraint failure, re-reads request/source/correction state
    and returns the deterministic controlled outcome.

Any validation or persistence failure inserts no entry.

## Read and integrity behavior

`find` and `findByOrder` are scoped by exact organization. They load the root
and all entries in canonical `(recorded_at, unsigned entry UUID)` order.

The adapter reconstructs accepted value objects and validates:

- exact root ownership and one trace per order;
- every entry belongs to the root and uses its currency;
- request and present source-fact uniqueness;
- correction target existence, same trace/stage/basis, and linearity;
- source shape and all canonical values.

Malformed or contradictory persisted data returns `IntegrityFailure`. An absent
or foreign trace/order returns `NotFound`. Reads do not require an active
organization and perform no status projection.

## Privacy and rendering

Organization, IDs, external order, marketplace, source system/reference,
currency, magnitude, timestamps, and correction relationships are not included
in aggregate `toString`, controlled error text, metrics, or logs.

TASK-0092 adds no telemetry or logging. Database exception, SQL, constraint, and
driver messages are swallowed into controlled results.

## Acceptance fixtures

One BRL trace for a `mercado-livre` order records expected facts:

```text
SALE / EXPECTED / ADDITION                 299.90
MARKETPLACE_COMMISSION / EXPECTED / DEDUCTION 41.99
SHIPPING / EXPECTED / DEDUCTION             18.40
ADVERTISING / EXPECTED / DEDUCTION            7.20
TAX / EXPECTED / DEDUCTION                   24.30
PRODUCT_COST / EXPECTED / DEDUCTION         143.20
```

Later actual facts record:

```text
SETTLEMENT / ACTUAL / ADDITION               65.31
PAYMENT_ACCOUNT / ACTUAL / ADDITION          65.31
BANK / ACTUAL / ADDITION                     65.31
```

The ledger preserves all nine exact facts and their provenance. It does not
claim that `65.31` is correct, calculate the `0.50` difference from the MKT-001
contribution, or declare a reconciliation status.
